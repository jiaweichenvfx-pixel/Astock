# 看长做短 V5.1 · 个人量化投研决策系统

「卖出优先、仓位管住、买点精准」的三维决策辅助系统。
**卖点是刹车，仓位是安全带，买点是方向盘。**

> ⚠️ 本系统仅提供决策建议，不连接券商、不自动下单。

## 快速开始

```bash
cd /Volumes/flame_stone/AI/DSH/AStock

# 1. 创建虚拟环境（已建则跳过）
/usr/local/bin/python3.13 -m venv .venv

# 2. 安装依赖
./.venv/bin/pip install -r requirements.txt

# 3. 启动
./.venv/bin/python run.py

# 浏览器打开 http://127.0.0.1:8000
```

首次启动会自动写入一个「满仓融资被套」演示账户，便于立刻看到卖出优先效果。
可点击右上角「载入演示」随时重置。

## 模拟回测 / 参数寻优 怎么用

三件事要分清：**回测选战法 → 寻优选参数 → 买卖点告诉你挂什么价**。

### 1. 模拟回测 `POST /api/backtest`：这只票适合哪套战法

把 15 套战法在同一段历史上并排跑一遍（T+1、涨跌停不成交、佣金万2.5、印花税、滑点0.1%），
输出四张表：

| 表 | 看什么 | 怎么读 |
|---|---|---|
| 综合分析 | 综合分第 1 名 | 综合分 = 收益35% + 捕获率30% + 买命中17.5% + 卖命中17.5%；先看它 |
| 买点/卖点准度 | buy_gap / sell_gap | 买点离波段低点几个点、卖点离高点几个点，越小越准 |
| 双均线卖点参数 | -3/+5、-5/+8、-7/+12 | 同一战法换止损止盈，看回撤与胜率的取舍 |
| 资金曲线 | 最优战法的净值 | 曲线抖不抖 = 你能不能拿得住 |

**别只看胜率**：胜率高可能是「3 笔交易里赚 2 笔」，样本太小；还要看盈亏比、交易次数、回撤。

### 2. 参数寻优 `POST /api/optimize`：同一战法，哪组参数最好

对每个战法遍历参数网格（如双均线 MA5/20、MA10/30、MA5/30、MA20/60），按
「胜率优先」或「收益优先」排名，并对 日线/周线/2小时/1小时/30分钟 五个周期各跑一遍。

- 胜率优先：剔除交易次数 < 3 的假高胜率（样本太少不算数）
- 被套降本推荐：只保留低吸/做T 类战法（布林带、RSI、网格、KDJ、CCI、低吸共振），
  要求「高胜率 + 有交易次数」，适合套牢盘反复做T降成本

### 3. 下一步买卖点 `POST /api/action_plan`：具体挂什么价

回测/寻优只告诉你「历史表现」，买卖点把它翻译成可执行的价格：

1. 用同一套规则复现当前持仓状态（信号收盘判定、次日开盘成交、止损 -12% 盘中触发）
2. 把「明日可能的收盘价」当作新 K 线追加，重算该战法信号
3. 在现价 ±30% 内逐档试探，找到离现价最近的买/卖触发价
4. 同时给：止损价、关键价位（MA5/10/20/60、布林上轨中轨下轨、20日高低、ATR14）、一句话结论

返回里的 `action.type` 就是该做什么：

| type | 含义 |
|---|---|
| `buy_now` | 今日收盘刚触发买入 → 明日开盘买入 |
| `sell_now` | 今日收盘刚触发卖出 → 明日开盘卖出 |
| `wait_buy` | 空仓等待，收盘站上/跌到触发价才买 |
| `hold` | 持仓继续持有，跌破卖出触发价或止损价才动 |
| `none` | 该战法当前无有效买点（±30% 内不触发） |

⚠️ 触发价是**收盘价条件**，成交价是次一交易日开盘（±滑点）——和回测口径一致。
不要把它当限价单价格用，而是「收盘前 5 分钟看一眼，满足了再挂次日开盘」。

前端位置：模拟回测结果顶部自动出现「📍 下一步买卖点」卡片；参数寻优每一行有「📍 买卖点」按钮（弹窗展示）。

### 4. 一键决策 `POST /api/playbook`：把上面三步串成一条流水线

点「🚀 一键决策」，后端按固定顺序跑完，只给一个结论：

1. **回测** 15 套战法（默认参数）→ 取综合分前 3 名
2. **寻优** 这 3 套战的参数网格
3. **样本外验收**：把 320 根切成前 70% / 后 30%，前段调参、后段检验
4. **采用规则**：调参必须在样本外也多赚 **>0.5 个点** 才采用，否则退回默认参数并打「⚠️ 过拟合」
5. 用最终战法 + 参数 → **买卖点**（触发价/止损价）

界面上会看到三段：`🏁 结论`（用了哪套战法、哪组参数、为什么）→ `📍 下一步买卖点` → `🧮 选战法+调参过程`（每套战的样本内/样本外、是否过拟合、最终参数）。

> 为什么要样本外：寻优是在同一段历史上反复挑最优，天然会拟合噪声；只有后 30% 没见过的时间段也能赢，参数才算可用。

## 精选选股里的两方向推荐 `GET /api/screener`

全市场扫描除了大盘动态，还出两份**带方向**的名单，每行都有「📍」直接算该周期的买卖点：

### 🧨 短线推荐（持股 2~10 天）

从**成交额前 40 只**里挑（先保证流动性），再按量价打分：

| 维度 | 规则 |
|---|---|
| 量比 | ≥2 放量 +30，≥1.5 +20，≥1.2 +10 |
| 当日涨幅 | +2%~+7% +20；涨跌停附近直接剔除（按板块阈值：主板 10%、双创 20%） |
| 5 日涨幅 | 0~15% +15；>15% 扣 5（短期过热） |
| 60 日涨幅 | 0~40% +15；>40% 减分 |
| 均线位置 | 站上 20 日线 +10 |
| 成交额 | ≥5 亿 +15 |

直接剔除：ST/退市、北交所（4/8/920）、成交额 <1 亿、股价 <3 元。

> 量比和 5 日涨幅不在行情快照里（新浪源没有），所以对前 40 只**补拉 90 根日线**补算。
> 首次约 10 秒，之后命中 SQLite 缓存很快。⚠️ 不能用线程池：akshare 的 py_mini_racer 不是线程安全的。

### 💎 长线持有推荐（持股 6 个月+）

从**核心池（ROE>15% + 增速>10%）**与**价值池（PE<15 或 PB<1）**合并后重新排序：

| 维度 | 规则 |
|---|---|
| ROE | >15% +25；10~15% +15；>60% 只 +15 并提示「是否一次性收益」 |
| 增速 | >10% +15；>0 +8；**>150% 扣 10** 并标「可能低基数」 |
| 估值 | PE<15 +15；PE<25 +8；PB<2 +8 |
| 市值 | >500 亿 +15；>200 亿 +10；>100 亿 +5 |
| 趋势 | 60 日 > -10% +8 |

### 行情源：东方财富 → 新浪兜底 → 腾讯补齐

东财快照被限频后（0.1 秒返回 0 条），全市场快照退化到新浪源，**没有 PE / PB / 市值 / 换手率**。
现在补了第三层：**腾讯行情**（`qt.gtimg.cn`，逐只/批量皆可，字段最全）。

| 层 | 提供什么 | 用在哪 |
|---|---|---|
| 东财快照 | 全市场 5000+ 只：价格/涨幅/成交额/量比/换手/PE/PB/市值 | 主源 |
| 新浪快照（兜底） | 全市场：价格/涨幅/成交额（字段少） | 东财挂了时 |
| **腾讯行情（补齐）** | 逐只：量比/换手/PE/PB/总市值/涨跌停价 | 只补候选池（≤50 只/次） |

- 只在快照字段缺失时才请求，一次批量 50 只，回写 SQLite 缓存 120 秒
- 补齐后 `data_quality.degraded = false`，界面显示「行情源：新浪(兜底) · 腾讯行情 40/40（PE/市值/换手已补齐）」
- 补齐后长线评分重新有估值维度（PE/PB/市值），短线用官方量比与换手率

### 数据源降级提示

行情源被限频时会退回新浪（没有量比/换手/PE/市值），此时接口返回
`data_quality.degraded = true`，界面顶部会明确写出「打分已降级」——不会假装数据齐全。

## 长线 / 中线 / 短线三档回测 `POST /api/horizons`

同一只票，用三种周期各跑一遍 15 套战法 —— 长线看周线、中线看日线、短线看 60 分钟：

| 档位 | 周期 | 样本 | 止损口径 | 适合 |
|---|---|---|---|---|
| 长线 | 周线 | 300 根（约 6 年） | 不设止损，拿住 | 趋势与估值回归 |
| 中线 | 日线 | 320 根（约 15 个月） | -12% | 波段 |
| 短线 | 60 分钟 | 200 根（约 2 个月） | -5% / 止盈 +8% / 10 根时间止损 | 情绪与节奏 |

⚠️ 三档**不是**同一套止损换周期：短线用 -12% 一周都碰不到，长线用 -5% 会被正常回撤洗出去。
周线回测用的是「周线上的战法信号」，不是把日线信号直接套到周线。

### 按市场情绪推荐

| 当前情绪 | 推荐 | 理由 |
|---|---|---|
| 火热（普涨/放量） | 短线 | 趋势延续性强，快进快出效率最高 |
| 温和 | 中线 | 波段最完整，日线级别最好做 |
| 寒冷（跌多涨少/缩量） | 长线 | 短周期噪声大、反复止损，宁可用长线拿住 |

### 换手门槛：短线就得有短线的频率

不同周期该有的交易频率不一样，所以每档先按换手筛一遍战法，再按综合分选：

| 档位 | 门槛 | 说明 |
|---|---|---|
| 长线 | ≥1 笔 | 6 年里 1~5 笔都正常（长线持有本身就是 1 笔） |
| 中线 | ≥2 笔 | 15 个月至少做 2 次 |
| 短线 | **≥5 笔** | 2 个月不到 5 笔（≈每月 2 次）不配叫短线，直接筛掉 |

不设门槛会出问题：综合分偏爱「笔数少 → 回撤小 → 胜率高」的战法，
结果短线档选出个 2 个月只交易 1 次的策略，名义短线、实质躺平。

每档还会给出换手画像：

- **笔数 / 平均持有天数 / 年化笔数**：判断这是不是该周期的节奏
- **费用拖累**：每笔往返约 0.3%（佣金+印花+过户+滑点），10 笔就是 3%，短线的收益一大半被吃掉
- **快参对照**：同一战法把参数调快（如 MA 5/20 → 3/8）后笔数和收益怎么变，直接用来看「高频到底赚不赚」

情绪只影响「建议做哪一档」，不修改历史数据。如果推荐的那档历史上不赚钱，
会自动退回历史表现最好的那一档，并提示「情绪与历史不一致」。

界面上：模拟回测卡片 → **🧭 长/中/短** 按钮，弹窗里三列并排，推荐的那档描蓝边，
每档都有「📍 这档的买卖点」按钮。

| 项 | 口径 |
|---|---|
| 担保比例 | **信用账户总资产 ÷ 融资负债**（券商口径），信用账户 = 标记为「信用」的持仓市值 + 信用可用资金 |
| 警戒线 | 150%（低于会被要求追加担保） |
| 平仓线 | 130%（低于会被强制平仓） |
| 还能跌多少 | `1 − 线 / 当前比例`，直接换算成「再跌 X% 触线」 |

- 比例线来自 `config.yaml` 的 `margin.warning_ratio / liquidation_ratio`
- 状态分级：`safe`（≥ 警戒+50）→ `warm` → `warning`（≤150）→ `danger`（≤130）
- **普通账户不参与担保比例计算**：券商不会因为你在普通账户有钱就不强平信用账户，
  合并计算会把 228% 虚报成 268%

持仓需要标记账户类型（`account_type: 普通 / 信用`），批量导入时可以带上。

## 持仓战法体检 `GET /api/portfolio_bt`

每只持仓 × **短（60分钟）/ 中（日线）/ 长（周线）** 三档 × 15 套战法，各自给出**前 5 名**。

界面上是「体检单」而不是「选秀榜」：

- 每只票三个标签：**15 套里几套赚钱 · 中位收益**（不是「最优战法 +127%」）
- 点开展开三档，每档显示：`15 套里 N 套赚钱 · 中位收益 · 同期买入持有 · 排名稳定性`
- 交易笔数 < 5 的战法整行灰掉并标「样本少」——4 笔交易的 75% 胜率没有统计意义

**为什么改成这样**（实测数据）：

| 检验 | 结果 |
|---|---|
| 把日收益打乱（毁掉所有形态）再回测 | 「最优战法」中位仍 +52.7%，最高 +244% |
| 前后两半窗口的策略排名相关性 | 11 只平均 **+0.05**（0 = 毫无关系） |
| 很多「最优」的交易笔数 | 1~4 笔，胜率置信区间宽到没有意义 |

所以**「最优战法」基本是路径的产物，不是这只票的属性**。真正稳定的是「共识度」：
五粮液、小米中线 **0/15 套赚钱**（说明没有可捕捉的技术节奏），中金黄金长线 14/15（有节奏），
这种信息才值得看。

- 持久化：结果写进 SQLite 表 `bt_cache`（**日期 × 代码 × 周期**），页面读取 3~5 毫秒；
  只补「今天还没算的那几行」，加一只新股只算它自己的 3 行，其它票直接复用；
  保留 90 天（`prune_bt`），卡片上可用日期下拉回看历史某天
- 自动刷新：后台预热线程每天第一次运行时会自动重算（上午打开程序就是当天数据）
- 手动重算：卡片右上「重新计算」按钮（约 10 秒，11 只票 × 3 档 × 15 战法）
- 缺数据会显式标注：港股没有 60 分钟线 → 短线显示「无数据」

从「持仓战法体检」里点任意一战法，弹出详情页：

## 选股策略对比（因子回测）`GET /api/factor/all`

选股用**短/中/长三套独立系统**，各自的股票池、特征、策略、再平衡频率、持有期都不同：

| 维度 | 短线 | 中线 | 长线 |
|---|---|---|---|
| 股票池 | 高换手活跃股 | 流动性好的趋势股 | 大市值龙头 |
| 特征 | 当日涨幅/量比/换手/连涨 | 20-60日趋势/均线/距前高 | 60-120日趋势/年线/长期波动 |
| 策略 | 涨停动能/放量突破/强势/3日动量/超跌反抽 | 温和放量/突破新高/动量/均线多头/低波动/组合 | 年线趋势/60日动量/长期低波动/组合 |
| 再平衡 | 每 2 日 | 每 5 日 | 每 20 日 |
| 持有期 | 5 日 | 20 日 | 60 日 |

**回测方式**：每套策略在自己的股票池里按自己的再平衡频率选 top5，
统计持有期内的平均收益，和全池基准比 → 按历史平均收益排名。

- 结果按日期缓存（`factor_{horizon}_{date}`），首次约 50 秒（拉 120 只历史），之后秒回
- **自动采用**：自选池入选时用每周期历史最优的策略（`watchpool` 的 `strategies` 参数）
- 界面「⚖️ 选股策略对比」卡显示三档各自的前 4 名，👑 为当前采用的
- 战法体检的三档表格用 `auto-fit` 自适应：窄屏自动堆叠，不会横向溢出压到右列

> ⚠️ 这本身也是「样本内选最优」，有同样的过拟合风险；好处是它会每天重算、可追踪、
> 有明确的基准对照，比拍脑袋选一套公式强，但别把排名当永恒真理。

## 市场环境闸门（做 T 专用）

实测：下跌市里各战法后 60 日平均收益 ——

| 战法 | 后60日 | 胜率 |
|---|---|---|
| J 值负值反转 | **+0.18%** | 39% |
| 布林带 | −1.46% | 47% |
| 网格做T | **−5.08%** | 47% |
| KDJ金叉 | **−6.49%** | 34% |

所以在「指数在 MA20 下方 且 跌多涨少」时，做 T 模块会：

- 禁止 `网格做T / KDJ金叉 / CCI顺势 / MACD / ATR通道`（实测负期望）
- 只允许 J 值类信号
- 判定为「环境不适合做 T」，不进入年化降本测算

## 胜率能延续吗（实测结论）

用你自己的 11 只票、500 个交易日，把样本切成前后两半做检验：

| 检验 | 结果 |
|---|---|
| 前半段平均胜率 | 49.2% |
| 后半段平均胜率 | **30.4%**（衰减 19 个百分点） |
| 前后胜率相关性 | **+0.23**（很弱） |
| 挑「前半最优」战法 → 后半胜率 | 37.6% |
| 随便挑一套战法 → 后半胜率 | 30.1% |
| **相对优势** | **+7.6 个百分点** |

结论：
- **绝对胜率不能延续**（跟着市场环境一起衰减）
- **相对优势能勉强延续**（+7.6pp，但别指望复制 60%+ 的胜率）
- 胜率与收益正相关（+0.52），所以「找高胜率战法」方向没错，只是别把数字当承诺

因此「解套降本」模块的年化降本**按胜率折算期望**，而不是假设每次都成功：

```
做T期望 = 价差 × (2×胜率 − 1) × 次数
```
界面上同时给「乐观（回测胜率）」和「保守（折算样本外）」两个数。

## 基本面趋势 `GET /api/fundamental`

只看最新一期的「扣非 < −30%」太晚。真实变化是渐进的：

```
赛力斯: +72% → +27% → −8% → −74% → −196%
                        ↑ 这里就该预警，而不是等 −196%
```

做法：取最近 8 个报告期的扣非净利同比，判定

| 判定 | 条件 | 含义 |
|---|---|---|
| 🔴 恶化预警 | ①连续 ≥2 期下滑且转负 ②**首次转负**（上期为正、本期为负）③扣非 ≤ −30% 深度下滑 | 比 −30% 阈值提前 1~2 个季度 |
| 🟠 增速走弱 | 连续 ≥2 期下滑但仍为正 | 还在增长，但要盯着 |
| 🟢 改善 | 连续 ≥2 期回升 | 选股加分 |
| ⚪ 平稳 | 其它 | — |

**已接入卖出信号**：`恶化预警` 会生成一条 **黄色（58 分）**「基本面连续 N 期恶化」信号，
进入指令流与今日待办（3 日内处理）；`增速走弱` 只在趋势卡片提示，不触发卖出。

界面上「📊 基本面趋势」卡片逐只显示，恶化标红、走弱标橙。

**业绩预告**：取最近两个报告期的预告（优先扣非），比正式财报早 1~3 个月；
与已披露数据差 30pp 以上时标「预告存疑」，以实际财报为准。

> 注意：扣非同比用的是**累计值**（Q1/Q2/Q3/Q4 口径不同），跨季度比较会有噪声，
> 所以用「连续两期下滑 >3pp」过滤；港股（小米）没有 A 股财报接口，显示无数据。

## 战法推荐的统一口径 `GET /api/recommend`

**问题**：以前四个地方各排各的 —— 体检按「综合分」、一键决策按「样本内收益」、
做 T 按「命中率+频率」、自选池用的是另一套选股因子，用户看到的推荐对不上。

**现在**：只有一份回测数据（`bt_cache`），不同**用途**用不同评价函数。

| purpose | 用于 | 权重 |
|---|---|---|
| `hold` | 持有节奏（体检） | 综合分 × 70% + 买卖点命中 × 30% |
| `trade` | 做 T 降本 | 命中 45% + 频率 30% + 「约 1% 捕获」25% + 60分钟 +12 |
| `buy` | 新开仓 | 命中 40% + 稳定性 30% + 频率 20% + 价差 10% |

硬性门槛：
- `trade`：笔数 ≥4 且单次均收益 > 0.302%（A 股往返成本）
- `buy`：笔数 ≥4、单次 > 成本、**排名稳定性 ≥ 0.25**（拒绝不可复现的排名）

同一只票三种用途可能给出不同答案，这是**设计如此**：

| 股票 | 持有节奏 | 做T降本 | 新开仓 |
|---|---|---|---|
| 长白山 | 布林带(日) | KDJ金叉(60分) | 布林带(日) |
| 中金黄金 | 网格做T(60分) | 网格做T(60分) | 网格做T(周) |
| 赛力斯 | 低吸共振(60分) | RSI超卖(60分) | KDJ金叉(周) |

`action_plan` 不指定战法时默认取 `hold` 的第一名；做 T 模块直接调用 `trade`。
**选股（自选池的因子）与择时（战法）是两层**，前者决定买什么，后者决定什么价位动手。

## J 值策略与监控 `GET /api/jwatch`

KDJ 的 `J = 3K − 2D` 会跑到负值（K/D 不会），是经典的超跌信号。实测（80 只 × 800 日，
基准「随便哪天买持有 20 日」= +5.33%）：

| 信号 | 次数 | 20日均值 | 超额 | 胜率 |
|---|---|---|---|---|
| 仅日线 J<−10 | 970 | +3.03% | **−2.30%** | 54% |
| 仅周线 J<0 | 4573 | +9.86% | **+4.53%** | 68% |
| 日线+周线共振 | 30 | +7.47% | +2.14% | 73% |
| 日+周+月三共振 | **0** | — | — | — |

结论：**日线单独超跌是负超额（接的是下跌中继）**，要等周线也进入低位才算真买点；
三周期同时负值 800 天里一次都没出现，等不到。

- 战法 `J值负值反转`（日线）与 `J值周线共振`（日线拐头 + 周线 J<0）都已注册，共 17 套
- 周线用**已完成周**计算，杜绝未来函数
- 界面「📉 J 值监控」卡片显示每只持仓的日 J / 周 J 与状态：
  共振买点 / 共振低位等拐头 / 周线低位+日线负值 / 周线低位 / 仅日线超跌 / 日线负值 / J值超买（高抛参考）

## 解套降本作战 `GET /api/rescue`

针对被套持仓，算清楚三件事：**还差多少回本、做 T 能降多少、几次能解套**。

| 指标 | 算法 |
|---|---|
| 回本需涨 | `成本 / 现价 − 1` |
| 做 T 股数 | 底仓的 30%，向下取整到 100 股 |
| 单次降本 | 价差 × 现价 × 做 T 股数 ÷ 总股数 ÷ 成本 |
| 需几轮 | `回本需涨 ÷ 单次降本`（超过 60 轮判「难解套」） |
| 做 T 战法 | 回测里「做 T 评分」最高的那套（见下） |
| 做 T 区间 | 该战法的买卖点（价差合理时）；否则用近 20 日震荡区间的 25%/75% 分位 |
| 单次价差 | 日均振幅的一半（不是箱体宽度），夹在 0.8%~4% |
| 年化降本 | 单次收益 × 每月 4 次 × 12 |

计划判定（按优先级）：
- 已盈利 → 可作减仓兑现来源
- 仓位不足（< 1 手可 T）→ 只能整仓处理
- **有卖出信号（红/橙）→ 优先减仓，不做 T**（下跌中做 T 等于反复接刀）
- 需 > 60 轮 → 做 T 难解套，考虑减仓换股
- 否则 → 做 T 降本

### 做 T 用哪套战法：不是「胜率最高」，是「做 T 评分最高」

```
做T评分 = 买卖点命中率 × 45% + 交易频率 × 25% + 单次价差覆盖 × 30%
        + 60 分钟档额外 12 分（做 T 就该用短周期战法）
```

- **命中率**：买点/卖点命中率均值，衡量高抛低吸准不准
- **频率**：交易笔数，衡量一年给多少次机会
- **价差覆盖**：单次平均收益必须 > 0.302%（A 股往返成本）
- 低于 50 分 → 直接判「节奏不适合做 T」，别硬做

只按胜率选会掉进坑里：一个三个月交易 3 次、胜率 90% 的战法，给你做 T 的机会太少。

现实约束写在 `rules.note`：**A 股 T+1，做 T 必须先用底仓高抛、再低吸买回；融资额度不能用于加仓做 T**。

当前账户算出来的结果：浮亏 19.7 万、回本平均需涨 117%、
做 T 一年能降本 5.4 万（覆盖 27.6%），结论是 **「做 T 能降本但解不了套，必须配合减仓」**。

## 战法周期权重（融资盘自动偏短线）`horizon_weights`

融资盘持有长线每天都在付利息，所以**战法权重按账户健康度动态调整**，不是固定的 40/35/25：

| 输入 | 影响 |
|---|---|
| 融资余额 / 净资产 | 融资占比越高，长线权重越低、短线越高 |
| 健康度分数 | < 40 分再往前压，优先短线快进快出 |
| 净资产 ≤ 0（资不抵债） | 按最大偏移处理 |

输出：
- `weights`：短线/中线/长线权重（合计 100%）
- `pool_size`：自选池三池只数按权重分配（合计 30，每档 6~16）
- `daily_interest` / `annual_interest`：融资利息成本
- `break_even_annual_pct`：长线**年化要赚多少才不亏利息**
- `hold_cost`：持有 20/60/120 天的利息成本

例（当前账户）：融资 22 万、净资产 37.1 万 → 短线 **55.1%** / 中线 38.2% / 长线 **6.7%**，
利息 39.1 元/天（年 1.4 万），长线持有 60 天利息成本 2349 元，年化要跑赢 **3.85%** 才不亏。

界面上：战法体检卡片顶部显示权重条，**★ 标出当前该优先看的档位**；自选池按 16/11/6 只分配。

## 数据日期跟随 A 股交易日

所有「日期」都取**最近一个已收盘的交易日**，而不是自然日（`adapter.data_day()`）：

- 周六 / 周日 → 回退到上一个交易日
- 交易日 09:30 前 → 回退到前一交易日（当天还没有数据）
- 交易日 09:30 后 → 当天

用到这个日期的：自选池入池/出池、战法体检缓存、信号复盘、净值快照、因子回测缓存、每日任务去重。
界面在休市时会显示「2026-10-23 · 今日休市 周五」和「数据截至 2026-10-23 收盘」，
不会把周日误当成数据日。

「今日待办」在休市时会自动切成**下一交易日**口径：

- 标题变「下一交易日待办」，顶部提示「今日休市 · 以下为 2026-10-26 开盘计划，今天不用操作」
- 每条动作带日期前缀，如「2026-10-26 限价 84.67 挂单（反弹价）」
- 复制文本的第一行也是「【今日休市，以下为 2026-10-26 的计划】」

## 自选池（短/中/长）自我迭代 `GET /api/watchpool`

与「持仓池」彻底分开：持仓 = 你真实持有的票；自选池 = 系统每天从精选股票里挑出来观察的票。

| 池 | 入选 | 剔除（走坏） |
|---|---|---|
| 短线 | 精选·短线打分靠前 | 跌破 MA10 或 5 日涨幅 < −6% |
| 中线 | 精选·中线打分靠前（趋势向上不过热） | 跌破 MA20 或 20 日涨幅 < −10% |
| 长线 | 精选·长线（卓越/低估） | 跌破 MA250 或 60 日涨幅 < −25% |

- 每池目标 10 只（`POOL_SIZE`，可调），当天刚进池的不复盘
- 每天收盘后自动跑一次（`warmup`），也可手动点「运行选股/复盘」
- **进出全部留痕**：`pool_members`（当前状态）+ `pool_history`（每一笔从进池到出池的完整记录）

### 选股有效性 `GET /api/watchpool` 里的 `eval`

用「进池价 → 出池价」的实盘收益，回答当初的精选策略到底对不对：

- 已出池笔数、命中率（收益 > 0）、平均/中位收益，按池分列
- 在池股票的浮盈（进池价 → 最新价）
- 结论：样本 ≥5 笔时自动判「有效 / 无效 / 待观察」

> 这是给「精选股票策略」打分的关键：正收益 → 精选有效；负收益 → 选股逻辑要改。
> 第一天入池后收益是 0%，要等几天有出池记录后才有统计意义。

## 净值曲线与杠杆监控 `GET /api/equity`

两条线一起看，回答「这套满仓融资的结构有没有在变危险」：

| 线 | 怎么来 | 用途 |
|---|---|---|
| **真实快照** | 每次计算决策时把账户状态写进 `equity_snapshots`（每天覆盖） | 从今天起累积真实净值 |
| **回溯估算** | 当前持仓股数 × 历史收盘价 + 当前现金 − 当前负债 | 立刻看清这组仓位过去跌了多深 |

回溯线的假设写得很明确：**持仓、现金、负债都没变过**，所以它只回答「如果一直拿着现在这些票，
我今天的账户会是多少」，不是真实历史。

指标：

- **距峰值**：当前净值 / 历史峰值 − 1
- **90 日最大回撤**：峰值到谷值的最深跌幅，并给出峰谷日期
- **融资比 + 30 日变化**：`融资比 37.2%（30日 +2.17pp）`
- **预警分级**：跟当前模式的 `leverage_max` 对齐 —— 超过上限 = ⚠️ warn，超过 1.5 倍 = 🔴 danger

> 港股在回溯里也会按 `fx.hkd_cny` 折算，不会把港币当人民币算。

## 卖出信号由什么决定（和战法回测无关）

三层结构，别混淆：

| 层 | 模块 | 依据 | 产出 |
|---|---|---|---|
| ① 卖出信号 | `engine/sell.py` | **固定规则**（4 类机制 + 模式参数 + 财务数据） | 该不该卖、多急、为什么 |
| ② 战法体检 | `engine/bt_store.py` | 15 套战法的历史回测 | 仅研究参考，**不产生卖出信号** |
| ③ 买卖点 | `engine/action_plan.py` | 你选的某个战法的触发条件 | 什么价位动手 |

①的具体判据（全部写死在配置里，不依赖回测）：

- **硬止损**：浮亏 ≤ 当前模式止损线（急救 −3% / 防守 −5% / 平衡 −7% / 进攻 −10%）
- **时间止损**：持仓 ≥ N 天（5/7/10/15）仍未创新高且收益 < 1%
- **基本面止损**：扣非净利同比 < −30%、ROE 同比降 5pp、ST
- **技术卖点**：MACD 顶背离、RSI > 80、放量滞涨（量比 > 1.5 且涨幅 < 2%）

基础分：硬止损 90 / 基本面 75 / 时间止损 65 / 技术 45~60；多信号叠加每个 +5（上限 15）；
卖飞防御每满足一条 −10（最多降一级）。最后 ≥80 红、60–79 橙、40–59 黄、20–39 绿、<20 持有。

> 所以你账户里那 4 只「橙色 75 分·基本面止损」是**财务数据触发**，跟短/中/长线战法没有关系。

## 今日待办 / 信号复盘 / 卖飞防御真正生效

### 1. 卖飞防御（原先三个输入全是空的）

但无论扣多少分**最多只降一级**。理由里会写「卖飞风险：连续 11 日主力净流入」。

> 之后命中 6 小时缓存。这段跑在后台预热线程里，不影响页面。

### 2. 今日待办 `GET /api/todo`

把卖出信号 + 买点 + 仓位目标压成一张**按顺序执行**的单子：

1. 红色卖出 → 开盘市价卖出（最优先）
2. 橙色卖出 → 今日内挂单
3. 黄色卖出 → 3 日内处理

## 性能：现在打开是秒开（原来是 20 多秒）

### 原来慢在哪

东财行情接口被限频后，全市场快照走新浪兜底源，**冷抓一次 11 秒**；而 `/api/summary` 每次都要跑
「快照 → 财务 → 历史 → 卖出 → 买点」整条流水线，于是首屏要等：

| 接口 | 优化前 | 优化后 | 做法 |
|---|---|---|---|
| `GET /api/summary` | **23.6 秒** | **0.002 秒** | 后台预热 + 只读缓存 |
| `GET /api/screener` | 13.4 秒 | 0.0015 秒 | 10 分钟缓存 + 预热 |
| `GET /api/refresh` | 11 秒（阻塞） | **0.003 秒** | 改成后台任务立即返回 |

### 现在的机制

1. **后台预热线程**（`app/warmup.py`）：启动 2 秒后跑第一轮，之后
   - 交易时段（工作日 9:00~15:30）每 **2 分钟**刷行情
   - 非交易时段每 **30 分钟**刷一次
   - 选股扫描单独按 **10 分钟**节奏
2. **接口只读缓存**：有缓存就立刻返回，用 `meta.stale` 标记新鲜度；没有缓存（真·冷启动）才算一次
3. **前端显示数据时间**：卖出横幅尾巴带「数据 16:00」，过期时显示「⏳后台更新中」并 15 秒自动重试
4. **刷新按钮不再卡住**：点击后后台重算，页面立刻可用，新数据算好自动拉回
5. **akshare 全局锁**：`py_mini_racer`（V8）不是线程安全的，后台线程与请求线程并发会 SIGTRAP 崩进程，
   所有 akshare 调用走 `_AK_LOCK` 串行化（单用户场景代价可忽略）

## 做成 Android App：三条路 + 现在能做什么

### 结论先说

**后端（FastAPI + akshare + SQLite）不适合塞进手机**：akshare 依赖 pandas/numpy，装在 Android 上体积几百 MB、还要处理 Python 运行时。
所以正确形态是 **手机当客户端 + 电脑/服务器当 API**，而不是"把 Python 打进 APK"。

| 路线 | 做法 | 工期 | 适合 |
|---|---|---|---|
| ① PWA（已具备） | 手机浏览器打开 → 添加到主屏幕，独立窗口、有图标 | 已完成 | 自己用，最快 |
| ② 套壳打包 | Bubblewrap/Capacitor 把同一个网页包成 APK/AAB | 3~7 天 | 要装 APK、上应用商店 |
| ③ 原生客户端 | Flutter/Compose 重写界面，后端 API 不变 | 3~6 周 | 要推送、离线、流畅动画 |

### 现在已经准备好的

- `static/manifest.webmanifest` + 192/512/maskable 图标 + `static/sw.js`（PWA 可安装）
- 手机布局：≤700px 单列、指数两行、按钮加高、安全区适配
- 访问口令（可选）：`ASTOCK_TOKEN=xxx` 时 `/api/*` 必须带 `X-Auth-Token`，手机首次用 `?token=xxx` 打开即可记住
- 启动时打印局域网地址：`--host 0.0.0.0` 会提示手机该访问哪个 IP

### 今天就能在手机上用

```bash
ASTOCK_TOKEN=你的口令 ./.venv/bin/python run.py --host 0.0.0.0 --port 8000
# 终端会打印：手机访问：http://10.0.x.x:8000
```

手机 Chrome 打开该地址（首次带 `?token=你的口令`），菜单里「添加到主屏幕」。

⚠️ **HTTP 局域网下只是快捷方式，不是独立 App**：PWA 安装与 Service Worker 都要求安全上下文（HTTPS 或 localhost）。
要真正「像 App 一样独立窗口」，二选一：

1. 用 cloudflared / ngrok 开个 HTTPS 隧道（个人用最省事）
2. 直接走路线 ② 打包成 APK

### 上架前还必须补的（提前准备清单）

| 事项 | 现状 | 要做什么 |
|---|---|---|
| 认证 | 单口令 | 换成设备绑定 token / JWT，防爆破 |
| 部署 | 本机 8000 | Docker + 云服务器，HTTPS（Caddy/Nginx） |
| 性能 | 首次全市场扫描 10~30 秒 | 后台定时预热（早 9:00 / 收盘后），API 只读快照 |
| 推送 | 无 | 卖出信号/买点 → FCM（原生）或 Web Push（PWA） |
| API 版本 | 无版本号 | 加 `/api/v1` 前缀，避免以后改接口把老客户端打挂 |
| 数据合规 | 仅供个人研究 | 不要公开分发行情数据；上架商店需声明数据来源与免责 |
